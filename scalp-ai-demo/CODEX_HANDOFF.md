# Codex 인수인계 — 웹 구현

프로젝트: **딥러닝 기반 ai 두피 관리 서비스**
기준일: 2026-10-27

이 문서는 웹 개발을 이어가기 위한 자료다. 포스터·영상 제작 파일과 편집 절차는 인수인계 범위에서 제외한다.

**핵심 상태: 현재 확보된 소스는 예시 데이터로 작동하는 정적 웹 프로토타입이다. 실제 AI 추론, 회원 인증, 서버 DB는 아직 연결되지 않았다.** 사용자가 별도로 가진 VS Code/GitHub 코드가 있다면 그 코드와 먼저 비교해야 한다.

## 현재 우선 결정 — 2026-10-27

사용자는 **시연을 우선하며, 웹 도메인 대신 기기 간에 파일을 전달하는 방식**을 선택했다. 현재 작업 기준은 로컬 `scalp-ai-demo` 폴더다. 아래에 남아 있는 실제 AI·인증·서버 DB 개발 계획은 향후 계획이며, 파일 시연보다 먼저 진행할 작업을 뜻하지 않는다.

- 전달 형식: 글꼴·샘플 이미지·CSS·JavaScript를 포함한 단일 HTML과 실행 안내를 담은 ZIP.
- 생성: 프로젝트 루트에서 `python scripts/package_demo.py` 또는 `py scripts/package_demo.py`.
- 결과물: `releases/scalp-ai-offline.html`, `releases/scalp-ai-offline.zip`.
- 실행: HTML을 브라우저로 직접 열거나 ZIP을 풀고 `scalp-ai-offline/index.html`을 연다. 받는 기기에 개발 도구나 서버 설치는 필요하지 않다.
- 기록: 브라우저에 저장한 개인 시연 기록은 전달 파일에 포함되지 않는다. 파일 경로·이름 변경과 브라우저 저장 정책에 따라 기존 기록 조회나 저장이 제한될 수 있다.
- 범위: 기존 화면·3장 입력·예시 데이터 표시를 유지한다. 휴대폰·태블릿 실행은 아직 확인하지 않았다.

## 1. 목표

두피 사진을 입력하면 각질량·피지량·모공 밀도·모발사이홍반을 분석하고, 결과에 맞는 관리 정보와 날짜별 변화 기록을 제공하는 웹 서비스를 만든다.

처음에는 실제 모델이 완성되기 전에도 서비스 흐름을 소개할 수 있도록 화면과 기본 상호작용을 구현했다. 당장은 이 화면을 파일로 전달해 안정적으로 시연하는 것을 우선한다. 실제 분석·저장·추천 연결은 이후 개발 방향이다.

| 항목 | 유지할 정보 |
|---|---|
| 작품명 | 딥러닝 기반 ai 두피 관리 서비스 — `ai` 소문자 |
| 이전 명칭 | 모니터링 / 모(毛)니터링. 새 화면 제목에 복원하지 않는다. |
| 학교·동아리 | 대림대학교 · 지공모 |
| 행사 표기 | 대림 Tech-Fair 2026 / 2026 대림대학교 창의융합 전공동아리 |
| 팀원 | 연일, 이승철, 김진형 |
| 지도교수 | 김영실, 박상윤 |

## 2. 주요 결정사항

| 항목 | 현재 결정 / 확인할 사항 |
|---|---|
| 프런트엔드 | HTML + CSS + 순수 JavaScript. npm 설치나 빌드 없이 실행한다. |
| 현재 전달 방식 | 단일 HTML 또는 ZIP을 기기 간 전달해 로컬 브라우저에서 실행한다. 패키징은 개발자가 수행한다. |
| 화면 구성 | 두피 분석 → 분석 리포트 → 관리 기록 → 맞춤 관리, 별도 서비스 소개 화면 |
| 디자인 | 단순한 배경, 민트·짙은 녹색 계열, 카드형 화면, 나눔고딕. 기존 디자인을 활용한다. |
| 분석 지표 | 각질량, 피지량, 모공 밀도, 모발사이홍반 |
| 판정 등급 | 정상 / 경증 / 중증. 기존 기획의 경중증은 중증에 통합한다. |
| 입력 장수 | **현재 웹은 3장 입력이다. 후속 제공 자료에는 1장 흐름이 있어 최종 사양을 확인해야 한다.** |
| 3장 종합 규칙 | 기존 기획은 다수결, 모두 다르면 가운데 등급. 화면에는 중앙값 방식이라고 설명했지만 실제 종합 코드는 없다. |
| 데모 표시 | 실제 모델이 연결되기 전까지 예시 데이터·시연용 표시를 유지한다. |
| 사진 저장 | 현재는 브라우저 미리보기만 한다. 서버 전송·영구 저장은 하지 않는다. |
| 기록 저장 | 현재는 날짜와 예시 등급만 localStorage에 저장한다. |
| 개발 진행 | 기존 저장소와 구현을 먼저 확인하고, 검토 가능한 작은 단위로 구현·검증한다. |

기존 기획의 기술 방향은 **Python + Flask + PyTorch**, Flask-Login, Werkzeug, Pillow, SQLite + Flask-SQLAlchemy, Jinja2, Chart.js, FullCalendar다. 이는 기획에 적힌 방향이며 현재 이 스택으로 구현되었다는 뜻은 아니다. 별도의 실제 프로젝트가 있다면 그 구조를 먼저 확인한다.

## 3. 넘겨받을 소스와 실행 방법

### 현재 시연 전달 파일

- `releases/scalp-ai-offline.html`: 코드와 모든 실행 자산을 포함한 단일 HTML.
- `releases/scalp-ai-offline.zip`: `scalp-ai-offline/index.html`, `README.txt`, `FONT-LICENSE.txt`를 포함한 전달용 패키지.

소스를 수정한 뒤 `python scripts/package_demo.py`로 시연 파일을 다시 생성한다. 받은 기기에서는 ZIP을 완전히 풀고 HTML을 브라우저로 열면 된다. 메신저 첨부파일 미리보기에서의 실행이나 모든 모바일 기기 호환을 전제로 하지 않는다.

### 이전 웹 작업에서 넘겨받은 원본

- `CODEX_HANDOFF.md`: 이 문서.
- `scalp-ai-web.zip`: 현재 웹 소스. 압축을 풀면 `scalp-ai-demo/` 폴더가 생긴다.

ZIP 안의 HTML, CSS, JS는 현재 작업본과 같다. 다운로드용으로 인수인계 문서를 포함하고 웹에서 쓰지 않는 중복 TTF 글꼴만 제외했다. 기존 이름의 `monitering-vscode-source.zip` 대신 위 파일을 기준으로 사용한다.

| 위치 | 이전 웹 작업 환경의 경로 / 주소 |
|---|---|
| 웹 작업본 | `/workspace/sites/monitering-techfair-2026` |
| 전달용 ZIP | `/workspace/scratch/2c2b8f1c2116/output/scalp-ai-web.zip` |
| 시연 웹 | https://monitering-techfair-2026.goofyseal6.chatgpt.site |

위 절대 경로와 주소는 이전 웹 작업 환경의 이력이며 현재 파일 시연에 필요하지 않다. 원본 ZIP은 Windows의 `scalp-ai-demo` 폴더로 가져왔다. 웹 주소·폴더명에 남아 있는 `monitering`과 사용자에게 표시되는 작품명은 구분한다. 이 작업본이 사용자의 GitHub 저장소에 반영되었다고 가정하지 않는다.

### 개발 중 선택적 로컬 서버 미리보기

파일 시연에는 아래 서버가 필요하지 않다. 소스는 `dist/index.html`을 브라우저로 직접 열 수 있고, 개발 중에는 다음 방법도 사용할 수 있다.

1. ZIP을 풀고 `scalp-ai-demo` 폴더를 VS Code에서 연다.
2. 이 문서를 같은 폴더에 둔다.
3. 해당 폴더의 터미널에서 실행한다.

```powershell
py -m http.server 5500 --directory dist
```

`python` 명령을 쓰는 환경에서는 다음과 같다.

```bash
python -m http.server 5500 --directory dist
```

브라우저에서 `http://localhost:5500`에 접속한다. VS Code Live Server도 사용할 수 있다. 웹 실행에는 별도 Python 패키지나 Node 패키지가 필요하지 않으며 글꼴·샘플 이미지도 포함되어 있다.

| 주소 | 화면 |
|---|---|
| `/#analysis` | 사진 입력 및 촬영 안내 |
| `/#report` | 예시 분석 결과 |
| `/#history` | 기록·그래프·캘린더 |
| `/#care` | 관리 안내·체크리스트 |
| `/#about` | 서비스와 팀 소개 |

아래 경로는 압축 해제한 `scalp-ai-demo` 또는 현재 웹 소스 루트 기준이다.

| `dist/app.js` | 화면 템플릿, 라우팅, 이미지 선택, 예시 결과, 저장·조회, 캘린더, 체크리스트 |

| `FONT-LICENSE.txt` | 글꼴 권리 안내 |
| `scripts/package_demo.py` | 소스와 실행 자산을 단일 HTML 및 전달용 ZIP으로 묶는 개발용 도구 |
| `releases/scalp-ai-offline.html`, `releases/scalp-ai-offline.zip` | 다른 기기에 전달할 시연 결과물 |

현재 패키지에는 백엔드 진입점, 모델 가중치, 학습 코드, DB 스키마, 실제 API 클라이언트, 자동화 테스트·CI가 없다. 그래프는 SVG, 캘린더는 JavaScript로 직접 만들었으며 현재 Chart.js·FullCalendar를 사용하지 않는다.

### `dist/app.js` 탐색표

| 식별자 | 역할 / 이어서 작업할 때 주의점 |
|---|---|
| `METRICS`, `GRADES` | 지표와 등급 정의. 고정 결과는 `[1, 0, 1, 0]`이다. |
| `EXAMPLES` | 2026-10-09, 13, 18, 23의 설명용 기록 4개 |
| `state` | 사진 3개, 로딩 여부, 리포트 날짜, 캘린더 위치, 저장 여부, 체크리스트 |
| `STORAGE_KEY` | `monitering-demo-records-v1`. 이름을 변경하면 기존 저장 기록 이관 여부를 고려한다. |
| `analysis()`, `slots()` | 사진 입력 화면과 3개 슬롯. 입력 장수를 바꾸면 문구·배열·버튼 조건을 함께 수정한다. |
| `readPhoto()`, `releasePhoto()` | 이미지 형식·10MB 제한·디코딩 확인, 미리보기 URL 생성 및 해제 |
| `case 'analyze'` | 700ms 뒤 예시 결과로 이동한다. 실제 추론·네트워크 요청은 없다. |
| `report()`, `metricCards()` | 리포트 표시. 고정 결과 대신 실제 분석 결과 상태를 참조하도록 변경할 부분 |
| `case 'save'` | 날짜와 고정 등급을 저장한다. AI 연동 시 이 부분도 실제 결과를 저장하도록 바꿔야 한다. |
| `readRecords()`, `allRecords()` | localStorage 읽기와 기본 예시 기록 합치기 |
| `lineChart()` | **EXAMPLES만 표시한다. 새로 저장한 기록은 그래프에 반영되지 않는다.** 최근 1주는 예시 마지막 2개를 표시한다. |
| `history()`, `calendar()` | 기록 표와 월별 캘린더. 표·캘린더는 사용자가 저장한 기록도 읽는다. |
| `care()` | 고정 관리 안내와 체크리스트. 개인화 추천 엔진은 없다. |
| `about()` | 서비스, 팀원, 교수, 현재/향후 기능 설명 |
| `render()`, `go()` | 해시별 화면 렌더링과 이동 |

### 현재 데이터 형식

등급 배열 순서는 **각질량 → 피지량 → 모공 밀도 → 모발사이홍반**이며, 값은 **0=정상, 1=경증, 2=중증**이다. 실제 모델의 클래스 순서와 일치하는지 별도 확인해야 한다.

저장 레코드는 현재 다음 형태다.

```json
{
  "id": "demo-생성시각",
  "date": "2026-10-27",
  "grades": [1, 0, 1, 0],
  "sample": false
}
```

`sample:false`도 사용자가 저장한 **예시 결과**라는 뜻이며, 실제 AI 분석 여부를 의미하지 않는다. 실제 분석 여부를 구분할 데이터 필드는 별도로 설계해야 한다. 서버 API 경로와 요청·응답 스키마는 아직 정해지지 않았다.

## 5. 완료한 작업

- 작품명 변경과 학교·동아리·팀원·지도교수 정보 반영.
- 5개 화면과 해시 기반 메뉴 이동.
- 사진 3장 선택·해제·미리보기. JPEG/PNG/WEBP, 장당 10MB 이하 검사 및 읽을 수 없는 이미지 처리.
- 샘플 일러스트로 즉시 체험하는 동작.
- 4개 지표의 고정 예시 리포트, 안내 문구, 브라우저 인쇄.
- 날짜·예시 등급의 브라우저 저장, 중복 저장 방지, 저장 기록 삭제.
- 월 이동·날짜 선택이 가능한 캘린더와 기록 표.
- 예시 그래프의 주간·월간 표시 전환.
- 관리 안내와 체크리스트, 반응형·인쇄 스타일.

사진은 서버로 전송하거나 localStorage에 저장하지 않는다. 새로고침하면 사진 선택과 체크 상태는 초기화되고 저장한 날짜·등급만 같은 브라우저에 남는다. 다른 기기·브라우저·사이트 주소 사이에 기록이 공유되지 않는다.

이전 웹 환경의 인수인계에서는 실제 소스와 README를 읽고, 이동용 ZIP의 주요 파일 일치 여부를 확인했다. 이후 Windows 작업 폴더로 원본 파일 11개를 가져와 원본 일치, JavaScript 문법, 로컬 서버 파일 응답을 확인했다. 브라우저 자동 실행 오류로 당시 화면·클릭 검증은 완료하지 못했다. 파일 시연본은 실제 사용할 기기에서 직접 열어 기본 동작을 확인해야 한다.

## 6. 남은 문제

현재 우선 확인할 항목은 **전달 파일의 오프라인 실행, 실제 시연 기기의 화면·사진 선택·기록 저장 동작**이다. 아래 표는 이전 실제 서비스 구현 계획의 미해결 항목과 당시 우선순위를 보존한 것으로, 지금 당장 서버·AI 구현을 시작하라는 뜻은 아니다.

| 우선순위 | 문제 | 필요한 작업 |
|---|---|---|

| P0 | 입력 장수 불일치 | 현재 웹 3장과 후속 자료의 1장 중 최종 요구사항을 확정한다. |
| P0 | AI 미연동 | 모델 가중치, 구조, 입력 크기·정규화, 클래스 매핑, 추론 코드를 확보한다. |
| P0 | 모델명 불일치 | 기존 기획의 모발사이홍반 모델은 DINOv2, 후속 자료는 DINOv3. 실제 파일을 기준으로 확인한다. |
| P0 | 성능 근거 미확인 | 학습/검증 분할 및 지표별 평가 자료가 없다. Macro F1 0.85 등의 수치를 확정 성능으로 표시하지 않는다. |
| P1 | 고정 결과가 여러 곳에 분산 | 분석, 요약, 지표 카드, 저장, 관리 안내를 하나의 실제 분석 결과 상태에 연결한다. |
| P1 | 그래프가 실제 저장 기록과 불일치 | 저장한 기록과 날짜 범위로 그래프를 계산한다. 현재 지표별 선택 기능도 없다. |
| P1 | 회원·서버 저장 없음 | 회원/게스트 정책, 인증, 기록 접근 권한, DB 저장을 구현한다. |
| P1 | 개인화 추천 없음 | 결과별 관리·상품 추천 기준과 근거 자료를 준비한다. |
| P1 | 실제 통신·추론 실패 처리 없음 | 로딩, 재시도, 시간 초과, 중복 요청, 모델 미설치·추론 실패 상태를 처리한다. |
| P2 | 개발 환경·테스트 정리 필요 | 실제 백엔드 추가 시 의존성, 설정 예시, 실행 문서, 핵심 로직 테스트를 함께 정리한다. |

기존 기획의 모델 구성은 각질량 DINOv3(B), 피지량 DINOv3, 모공 밀도 EfficientNet-B4, 모발사이홍반 DINOv2다. 후속 자료에서는 모발사이홍반도 DINOv3로 설명했다. 현재 웹 소스에서는 어느 모델도 로드하지 않는다.

## 7. 다음 할 일

1. **시연 기기 확인:** 실제 사용할 기기와 브라우저에서 전달 파일을 직접 연다. 모바일 실행은 별도 확인한다.
2. **파일 시연 확인:** 인터넷 연결 없이 샘플 체험 → 리포트 → 기록 저장 → 캘린더 → 관리 안내 → 인쇄 흐름을 확인한다.
3. **사진 선택 확인:** 시연 기기에 준비한 사진 3장을 선택하고, 선택 해제와 잘못된 형식·크기 안내를 확인한다.
4. **최종 파일 전달:** 필요한 수정은 `dist/`에 반영하고 패키징을 다시 실행한다. 실행 안내와 함께 ZIP을 전달한다. 개인 저장 기록은 함께 이동하지 않는다.

### 파일 시연 이후의 실제 서비스 개발 계획

1. **기준 프로젝트 확인:** 실제 작업할 폴더·저장소와 기존 변경사항을 확인한다. 별도 구현이 없다면 전달한 정적 웹을 시작점으로 사용한다.
2. **현재 동작 실행:** 샘플 체험 → 리포트 → 기록 저장 → 캘린더 → 관리 안내를 확인한다. 기존 디자인을 유지한다.
3. **입력·결과 계약 확정:** 사진 1장/3장, 4개 지표의 클래스 순서, 전처리, 3장일 경우 종합 규칙을 결정한다.
4. **분석 결과 상태 분리:** 예시 데이터 공급과 실제 분석 호출을 분리하고, 리포트·저장·추천이 같은 결과 상태를 참조하게 정리한다.
5. **실제 분석 한 흐름 구현:** 이미지 수신 → 전처리 → 모델 추론 → 결과 반환 → 리포트 표시를 먼저 완성한다. 실패를 예시 성공 결과로 대체하지 않는다.
6. **저장·조회 구현:** 회원/게스트 정책과 DB를 연결한 뒤 그래프·표·캘린더가 같은 기록을 사용하도록 수정한다.
7. **추천 연결 및 검증:** 결과별 안내를 연결하고 실제 사용자 흐름, 모바일 화면, 오류 상태를 검증한다.

모델 파일이 아직 없으면 분석 호출 구조와 명시적인 데모 모드까지 준비할 수 있다. 실제 모델을 검증하지 않은 상태에서 AI 구현 완료라고 표시하지 않는다. 이 하위 절의 순서는 후속 개발 계획이며 현재 파일 시연 작업에서 새로 개발한 내용은 아니다.

### 변경 후 확인 기준

- 사진 선택·삭제와 형식·크기·읽기 오류 처리가 동작한다.
- API 결과의 지표·등급이 리포트와 저장 데이터에서 일치한다.
- 실패·시간 초과·중복 요청을 처리하고 로딩 상태가 정상 종료된다.
- 그래프·표·캘린더가 동일한 데이터와 실제 날짜 범위를 사용한다.
- 실제 기록과 예시 기록을 구분한다.
- 회원 기능을 추가하면 다른 계정의 기록에 접근할 수 없도록 검증한다.
- 테스트는 클래스 매핑, 채택한 종합 규칙, 실패 응답, 기록 권한처럼 오류 영향이 큰 부분부터 작성한다.
