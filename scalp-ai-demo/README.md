# 딥러닝 기반 AI 두피 관리 서비스

두피 사진 1~3장을 네 개의 실제 PyTorch 모델로 분석하는 **대회용 로컬 시연 웹**입니다. Flask/Waitress가 HTML/CSS/JavaScript 화면과 API를 같은 주소에서 제공합니다. 로그인, 계정별 기록, 분석 등급에 따른 생활 관리 안내를 지원합니다.

## 실행

이 PC에서는 `start.cmd`를 실행하거나 프로젝트 폴더의 PowerShell에서 실행하세요.

```powershell
powershell -ExecutionPolicy Bypass -File .\start.ps1
```

접속: **http://127.0.0.1:8000**. 종료는 서버 터미널에서 Ctrl+C. 포트 변경은 `start.ps1 -Port 8001`입니다. 기본 접속 범위는 이 PC입니다. `dist/index.html` 직접 열기나 Live Server는 AI·DB 서버를 실행하지 않습니다.

새 PC는 Python 3.11~3.14, 모델 파일을 준비하고 최초 한 번 `setup.ps1`을 실행하세요. 설치는 별도 `.venv`에 CPU PyTorch와 의존성을 설치합니다. 모델은 자동 다운로드하지 않습니다.

## 사용 흐름

1. **사진 분석**에서 사진 준비 → 사진 선택 → 확인 후 분석을 진행합니다. JPG/PNG/WEBP, 장당 10MiB·2,000만 화소 이하, 최대 3장입니다. 분석 버튼을 누를 때만 전송합니다.
2. 결과 화면에서 **오늘의 결과 저장하기**를 누르면 **내 기록**에서 다시 볼 수 있습니다. 사진별 결과도 펼쳐 볼 수 있으며 비율 수치는 표시하지 않습니다.
3. **맞춤 관리**는 현재 결과 또는 가장 최근 저장 기록의 등급을 사용합니다. 기본 습관 3개와 추가 관리 안내를 제공합니다. 새 피지는 유일 때 추가 안내를 표시하고 무일 때는 표시하지 않으며, 다른 항목은 정상 이외 결과에 안내를 추가합니다. 항목별 추가 이유와 참고 출처를 확인할 수 있습니다. 오늘의 체크는 로그인한 계정에 날짜별로 저장됩니다.
4. **촬영 가이드**는 촬영 방법과 준비 체크를 제공합니다.

관리 문구는 분석 등급에 따라 선택하는 생활 관리 정보입니다. 별도 추천 AI, 질병 진단, 치료 처방, 제품 추천을 구현한 것은 아닙니다. 탈모 여부·모낭사이홍반 두 모델의 학습 전처리는 아직 확인 중이므로 해당 결과는 관찰 참고용입니다.

## 회원과 저장

닉네임과 **시연 전용 비밀번호**로 가입하고 로그인합니다. 실제 사용 중인 비밀번호나 생년월일은 입력하지 않도록 안내합니다. 성별·나이·이메일은 수집하지 않으며 복잡도 조건이나 닉네임 중복 확인 화면도 없습니다.

동일 닉네임에 서로 다른 비밀번호를 사용하는 계정을 만들 수 있습니다. 동일한 닉네임·비밀번호 조합은 기존 계정 로그인을 안내합니다. 내부 계정 ID로 기록을 구분합니다. 비밀번호는 Werkzeug 해시로 저장하며, HttpOnly·SameSite=Lax 쿠키와 서버 DB 세션을 사용합니다. 세션은 최대 7일 유지되고 로그아웃 시 폐기합니다. 일반 회원의 비밀번호 찾기·이메일 인증·소셜 로그인은 범위에 포함하지 않습니다. 관리자는 아래 운영 화면에서 회원에게 임시 비밀번호를 발급할 수 있습니다.

- 로그인 상태: SQLite `data/scalp.sqlite3`에 계정·세션·분석 결과·날짜별 관리 체크를 저장합니다. 다른 계정의 기록을 조회하거나 삭제할 수 없습니다. 서버를 다시 실행해도 유지됩니다.
- 비회원: 기존 localStorage `scalp-ai-model-records-v2`에 결과를 저장합니다. 체크는 현재 페이지 사용 중에만 유지됩니다. 계정 전환 시 다른 계정 화면과 결과를 비우며, 비회원 기록을 자동으로 특정 계정에 옮기지 않습니다.
- 사진은 분석 메모리에서만 처리하고 서버·DB·localStorage에 저장하지 않습니다. 원본 파일명도 기록에 저장하지 않습니다.
- 계정에 저장할 수 있는 결과는 해당 로그인 상태에서 서버가 발급한 서명을 가진 분석 결과입니다. 클라이언트가 결과를 바꾸거나 다른 계정으로 넘기면 저장을 거절합니다.

`SCALP_DB_PATH`로 DB 위치를 지정할 수 있습니다. 기본 `data/`, `.runtime/`, 모델, 가상환경, 검사 결과와 백업 ZIP은 Git에서 제외합니다. DB를 옮기려면 서버를 종료한 뒤 DB 파일을 별도로 백업하세요. 이전 코드 백업에는 계정 DB가 없으며, 이번 피지 교체 전 백업에는 일관된 SQLite 사본도 포함했습니다. 브라우저 기록은 백업에 포함하지 않습니다. 현재 구성은 로컬 시연 기준입니다.

## 관리자 운영

일반 회원과 관리자는 같은 로그인 화면을 사용합니다. 관리자로 로그인하면 상단 **관리자 페이지** 메뉴가 표시되며 `/#admin`에서 운영 현황 → 회원 목록 → 모델 상태 → 최근 작업 내역을 확인할 수 있습니다.

- 운영 현황은 전체 계정·일반 회원·저장된 분석 결과·관리 날짜 수입니다. 비회원 브라우저 기록이나 저장하지 않은 분석 실행 횟수는 중앙 집계하지 않습니다.
- 회원 목록에서 닉네임과 **계정 ID**를 함께 확인합니다. 같은 닉네임의 계정도 ID별로 초기화·삭제합니다. 회원 분석 결과의 세부 내용이나 사진을 열람하는 화면은 추가하지 않았습니다.
- **비밀번호 초기화:** 새 임시 비밀번호를 한 번 표시하고 모든 기존 로그인을 해제합니다. 임시 비밀번호는 기존 비밀번호 및 같은 닉네임의 다른 계정과 겹치지 않도록 발급합니다. 화면을 닫거나 다른 페이지로 이동하면 표시를 지우며, 비밀번호 원문을 DB·브라우저 저장소·관리 작업 내역에 기록하지 않습니다.
- **기록 초기화:** 선택한 일반 회원의 분석 결과와 관리 체크를 함께 삭제합니다. 계정은 유지합니다. 옛 분석 저장 서명은 무효화되어, 열려 있던 화면에서 이전 결과를 다시 저장할 수 없습니다.
- **계정 삭제:** 선택한 일반 회원과 그 회원의 세션·분석 결과·관리 체크를 함께 삭제합니다. 초기화·삭제 전 대상 ID와 영향받는 기록 수를 확인합니다.
- 관리자 계정은 운영 화면에서 변경·삭제하지 않습니다. 관리 작업 내역에는 실행자·대상 ID와 닉네임·시각·처리 건수만 보관합니다. 삭제된 회원의 작업 내역도 남습니다.
- 모델 상태는 현재 준비 여부·표시 기준·모델 설정 식별자와 로딩 실패 원인입니다. 모델 재학습·가중치 교체·정확도 측정 기능은 포함하지 않습니다.

관리자 권한은 매 API 요청 시 DB에서 확인합니다. 회원가입 요청의 `role` 값으로 권한을 높일 수 없습니다. 기존 DB는 시작 시 `role=user`, `result_epoch=0`을 추가하는 방식으로 전환하며 계정 ID·비밀번호 해시·기록·기존 세션을 보존합니다. 관리자 초기화는 데이터 버전도 갱신하여 이전 저장 서명을 차단하고, 새 웹은 버전 변경 시 현재 결과·사진·개인 및 관리자 캐시를 비우고 계정 정보를 다시 불러옵니다.

최초 관리자나 추가 관리자는 **로컬 운영자 터미널**에서 생성합니다. 웹에는 관리자 가입 기능이나 고정 기본 비밀번호가 없습니다.

```powershell
.\.venv\Scripts\python.exe scripts\manage_admin.py create --nickname "운영자"
```

위 명령은 비밀번호를 두 번 숨김 입력받습니다. 비밀번호를 자동 생성하여 출력하려면 다음처럼 실행합니다. 생성된 비밀번호는 운영자가 별도로 보관하세요. 실행 파일이나 문서에 실제 운영 비밀번호를 넣지 않습니다.

```powershell
.\.venv\Scripts\python.exe scripts\manage_admin.py create --nickname "운영자" --generate-password
```

`--database PATH`는 `create` 앞에 지정합니다. 미지정 시 서버와 동일한 `SCALP_DB_PATH` 또는 `data/scalp.sqlite3`를 사용합니다. 생성된 계정은 서버를 다시 실행해도 유지됩니다.

## 모델과 판정

| 항목 | 가중치 | 출력 | 화면 등급 |
|---|---|---:|---|
| 각질 | `7_4level_fold0_각질.pth` | 4 | 정상 / 경중등도 / 중증 |
| 피지 유무 | `sebum_fold0.pth` | 3 → 2 | 무 / 유 |
| 탈모 여부 | `best_model_v11_augment_탈모.pth` | 3 | 정상 / 경증 / 중증 |
| 모낭사이홍반 | `FINAL_3CLASS_p010_fold0_모낭사이홍반.pth` | 3 | 정상 / 경증 / 중증 |

모델 검색은 기존 `SCALP_MODEL_DIR` → 프로젝트 `models/`(4개 모두 있을 때) → 사용자 `Downloads/scalp_4indicator_models` 순서를 유지합니다. 자동 검색에서 새 피지 파일이 없으면 프로젝트 `model_packages/sebum/weights/sebum_fold0.pth`를 사용합니다. `SCALP_MODEL_DIR`나 코드에서 명시적으로 모델 폴더를 지정했다면 네 파일 모두 그 폴더에 있어야 하며 다른 경로로 우회하지 않습니다. `torch.load(weights_only=True)`와 `load_state_dict(strict=True)`로 로드합니다. 누락·실패 시 분석을 차단하고 예시 결과로 대체하지 않습니다.

각질은 제공된 `각질량 코드/train.py`, `test_eval.py`를 대조해 수정했습니다.

- 원시 클래스는 **0=정상(학습 코드의 양호), 1=경증, 2=중등도, 3=중증**입니다. 0번도 사용합니다.
- **확률을 `[p0, p1+p2, p3]`으로 합산한 뒤** 최댓값으로 정상·경중등도·중증을 선택합니다. 원시 argmax를 선택한 다음 단순 치환하는 방식과 다릅니다.
- 이미지를 bicubic으로 **384×384 직접 리사이즈**하고 ImageNet 정규화합니다. 중앙 crop은 하지 않습니다. CLS와 prefix token을 제외한 patch 평균을 연결하는 forward도 학습 코드와 대조했습니다.
- 현재 각질 가중치는 `best_models/seed42_fold0.pth`와 SHA256이 일치하는 **단일 체크포인트**입니다. 제공된 6개 모델 앙상블을 적용한 것은 아닙니다. 학습 자료의 앙상블 성능을 현재 웹의 성능으로 표시하지 않습니다.

피지는 사용자가 승인한 `각질, 피지.zip`의 새 모델로 교체했습니다.

- 원시 출력은 **0=정상, 1=경증, 2=중등도이상** 세 개입니다. 최종 출력은 **`[p0, p1+p2]`을 먼저 합산 → 무/유 중 최댓값**입니다. 예를 들어 `[0.40, 0.35, 0.25]`는 원시 0번이 가장 높아도 최종 판정은 **유**입니다. 동률은 제공 코드처럼 첫 항목인 무를 선택합니다.
- `model_packages/sebum/predict.py`는 제공 파일과 바이트 단위로 같은 원본입니다. 이 모듈의 `ScalpNet`을 직접 사용하며, 마지막 네 블록의 LayerNorm·학습 attention pooling·CLS 연결(6144차원)과 보조 `head4`를 그대로 유지합니다. 단순 CLS/patch 평균 분류기로 대체하지 않습니다.
- 입력은 RGB → **384×384 bicubic 직접 리사이즈** → ImageNet 정규화입니다. 모델은 한 번 로드하고 사진마다 원시 출력만 구한 뒤, 웹의 여러 사진 종합 규칙으로 연결합니다. 공급 모듈의 CLI나 설치 명령을 서버에서 실행하지 않습니다.
- 새 가중치 SHA256은 `d5519a5f3c0c21c25cf18d312f41b72a2ef67a3db556605b0f8d79314f4319d0`입니다. 원래 다운로드 폴더의 `best_v3_피지과다.pth`는 덮어쓰지 않았습니다.
- 실행 의존성 `timm`을 **1.0.28**로 맞췄습니다. 공급 패키지의 요구사항 원본은 보관하고, 기존 웹의 Pillow 버전 범위는 유지합니다. 웹 환경 전체를 공급자의 학습 환경으로 교체한 것은 아닙니다. 설치된 환경에서 공급 코드와 텐서·출력 일치를 직접 검사합니다.
- 사용자 요청에 따라 화면에는 **무/유만 표시하며 확률은 숨깁니다**. 공급 문서의 확률 표시 문구를 사용자 지시보다 우선하지 않습니다. 공급 코드의 `retake` 필드는 이번에 새 UI 기능으로 추가하지 않았습니다.

탈모는 384 → crop 380, 홍반은 392 → crop 392를 유지합니다. 이 두 모델은 학습 당시 설정을 확인하지 않았습니다. `labels_confirmed`는 표시 등급 확인, `settings_verified`는 제공 코드의 전처리·forward 확인으로 구분하며 현재 각질·피지만 후자가 true입니다. `model_config.json`이 설정 원본이며 변경 후 서버 재시작이 필요합니다.

여러 사진은 **원시 클래스별 확률 평균 → 모델별 최종 등급 판정** 순서로 종합합니다. 기획서의 중앙값 방식으로 바꾸지 않았습니다. 원시 `class_index`·`confidence`와 최종 `grade_index`·`grade_probabilities`·`grade_confidence`는 별도 API 필드입니다. 확률은 내부 계산과 기록 호환에만 사용하며 질환 확률이나 정확도를 뜻하지 않습니다.

## 이전 기록

기존 브라우저 기록을 삭제하지 않습니다. 저장된 원시 네 값으로 각질 등급을 새 합산 규칙에 맞춰 표시하고, 예전 256 전처리 기록에는 **이전 분석 설정의 기록** 안내를 표시합니다. 이는 사진을 다시 분석한 결과가 아닙니다. 새 384 전처리를 적용하려면 원본 사진을 다시 분석해야 합니다. 이전 피지 모델의 정상·경증·중증 결과는 그대로 표시하고 **이전 피지 모델의 기록** 안내를 붙입니다. 다른 모델의 원시값을 새 유무로 재해석하지 않습니다. 새 판정은 원본 사진으로 다시 분석해야 합니다. 그래프는 같은 모델·설정 식별자의 기록끼리 비교하며, 새 피지는 세 등급 축에서 제외하고 별도 **무/유 두 단계 그래프**에 표시합니다.

## API와 파일

| 주소 | 역할 |
|---|---|
| `GET /api/health` | 모델 준비 상태·설정 확인 상태 |
| `POST /api/analyze` | multipart `photos` 1~3장, 실제 분석 |
| `GET /api/auth/me` | 현재 로그인 계정 |
| `POST /api/auth/register`, `/api/auth/login`, `/api/auth/logout` | 가입·로그인·로그아웃 |
| `GET`, `POST`, `DELETE /api/records` | 계정 기록 조회·저장·전체 삭제 |
| `GET`, `PUT /api/care-checks` | 계정의 날짜별 관리 체크 |
| `GET /api/admin/overview`, `/api/admin/users`, `/api/admin/actions` | 관리자 운영 현황·회원 목록·작업 내역 |
| `POST /api/admin/users/<id>/reset-password` | 일반 회원 임시 비밀번호 발급 |
| `POST /api/admin/users/<id>/clear-data` | 일반 회원 기록·관리 체크 초기화 |
| `DELETE /api/admin/users/<id>` | 일반 회원 계정·관련 데이터 삭제 |

`server.py`는 HTTP·업로드, `accounts.py`는 DB·인증·결과 저장, `inference.py`는 모델 추론과 원본 피지 모듈 연결, `model_packages/sebum/`은 수정하지 않은 제공 코드·연동 문서·원본 SHA256 매니페스트, `dist/app.js`는 화면·기록 연결, `dist/admin.js`는 관리자 화면과 조작, `dist/care.js`는 등급별 관리 문구를 담당합니다. JSON 변경 요청은 같은 출처와 JSON 형식을 검사합니다. 웹이 보내는 계정 식별 헤더를 현재 세션과 대조해 다른 탭의 계정 전환 시 잘못된 계정에 저장하지 않도록 막습니다. 모델 준비 전 503, 동시 분석 중 429, 잘못된 입력 400, 용량 초과 413을 반환합니다.

## 검증

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
node --check dist\app.js
node --check dist\care.js
node --check dist\admin.js
```

관리자 권한·기존 DB 전환·임시 비밀번호 충돌 방지 검사를 포함한 단위 테스트 56개가 통과했습니다. 새 피지 패키지·기존 각질 학습 코드와의 대조 검사, 실제 모델을 이용한 웹·회원 브라우저 검사도 통과했습니다. 대조 검사는 각 3장의 텐서·출력이 일치하는지 확인하며 모델 정확도를 측정하지 않습니다. 실제 모델을 사용하는 두 브라우저 검사도 별도로 실행합니다.

제공된 학습 폴더의 정의와 단일 가중치 출력을 직접 비교:

```powershell
.\.venv\Scripts\python.exe scripts\verify_flakes_training.py
.\.venv\Scripts\python.exe scripts\verify_sebum_package.py
```

학습 폴더에 쓰거나 학습 진입점을 실행하지 않습니다. 각 검사는 정규화 텐서·logits·합산 확률·최종 판정을 3장으로 대조합니다. 피지 검사는 ZIP과 패키지 원본 일치, 엄격하게 로드한 전체 가중치 일치, 공급 `ScalpPredictor.predict()` 결과까지 확인합니다. 이 검사는 구현의 일치를 확인하며 정확도를 평가하지 않습니다.

서버 실행 후 기존 분석 흐름 검증 및 별도 임시 DB 서버에서 회원 흐름 검증:

```powershell
.\.venv\Scripts\python.exe scripts\smoke_web.py
.\.venv\Scripts\python.exe scripts\smoke_accounts.py
.\.venv\Scripts\python.exe scripts\smoke_admin.py
```

회원·관리자 브라우저 검사는 별도의 임시 SQLite DB와 서버를 사용하며 실제 계정 DB를 초기화하지 않습니다. 관리자 검사는 접근 차단, 임시 비밀번호·로그인 해제, 확인창 취소·초기화·삭제, 작업 내역, 데이터 버전 변경과 모바일 표시를 확인합니다.

사진 선택 검사는 실제 선택 버튼으로 파일 선택창을 연 뒤 창 복귀 focus → 파일 선택 이벤트 순서를 확인합니다. 여러 장 선택·개별 슬롯·취소·일시적인 계정 확인 실패에서도 입력과 기존 사진을 유지하는지 검사합니다.

개발 의존성은 `requirements-dev.txt`, 브라우저는 설치된 Chrome/Edge headless를 사용합니다. `PLAYWRIGHT_CHROMIUM_EXECUTABLE`로 경로를 지정할 수 있습니다. 실제 모델과 합성 사진으로 분석 연동을 검사하며 합성 사진으로 임상 정확도를 평가하지 않습니다. 화면 검증 결과는 `test-results/`에 저장합니다.
